# 实验 3：关键证据共同窗口覆盖率

记录日期：2026-11-25。

本文固定挑战集的证据组织指标、计数规则和项目验收目标。该指标为本项目定义的诊断指标，
不声称是会议摘要领域通用标准。本文记录指标方案与已核对的开发结果，未新增自动汇总评分程序。

## 1. 指标目的

判断一个会议事项所需的分散证据，是否完整进入至少一个 specialist 的实际输入窗口。
例如，开头提出方案、末尾修订方案：两段证据共同可见，有助于 specialist 理解变化，
但不保证其理解正确，也不保证最终摘要正确。

英文名称：**Key Evidence Co-location Coverage**。

## 2. 定义与公式

评估前为每个目标事项标注理解它所必需的原文证据范围。一个事项可以需要两段或更多段证据，
不限于会议开头、末尾，也不限于决策变更。

设目标事项共有 N 个；事项 i 的必要证据对应源 token 位置集合 E_i；
specialist 窗口 j 实际收到的源 KV 位置集合为 W_j。

```text
hit(i) = 1，若存在至少一个窗口 j，使 E_i 完全包含于 W_j；否则为 0。

关键证据共同窗口覆盖率 = sum(hit(i)) / N
```

N = 0 时记为 N/A，不记为 0% 或 100%。

## 3. 固定计数规则

1. **按事项计数。** 每个预先标注的事项只计一次，不按方向、窗口数或匹配次数重复计数。
2. **完整共同可见才命中。** 必要证据分别出现在不同 specialist 中，不算命中。
3. **至少一个窗口即可。** 不要求首尾双向检索成功，也不要求所有 specialist 都收到证据。
4. **按实际输入计算。** 看合并、去重后的 KV positions，而不是候选排名、余弦分数或文字提及。
5. **不只看最终汇总。** 两段证据仅在最终汇总 agent 的全局 selected KV 中共同存在，不算局部窗口命中。
6. **不要求一定来自新检索。** 原始窗口已完整包含必要证据，同样计命中；用 baseline 对照识别额外收益。
7. **全局选择遗漏也算未覆盖。** 若任何必要证据被 selector 丢弃，不从事项分母中删除。
8. **源位置是可审计代理。** KV 行可见不等于模型实际关注；保留的全文上下文化 KV 也可能包含其他位置的信息影响。

优先使用准确的源 token 范围。若只有完整 speaker block 的审计范围，可用整块包含关系进行保守核对，
并披露粒度；不能把“块与标注范围有部分重叠”直接视为完整证据覆盖。

执行失败、损坏文件或缺失审计数据应另报数量；没有可核对记录时标为不可评估，不能悄悄排除后
仍声称评估了全部目标。正式结果同时报告计划事项数、可评估事项数、失败/缺失数和实际命中数。

## 4. 与其他指标的区别

| 指标 | 计数对象 | 能说明什么 | 不能说明什么 |
|---|---|---|---|
| 关键证据共同窗口覆盖率 | 事项 | 必要证据是否共同交付给局部 specialist | 理解、推理、最终摘要是否正确 |
| 方向检索命中率 | 有向关联 | 某一发言能否检索到另一发言 | 独立事项的成功率；双向关联不是独立样本 |
| 最终目标事项正确率 | 事项 | 摘要是否正确表达最终状态与关键细节 | 所有未标注内容的事实准确性 |
| ROUGE / BERTScore | 摘要与参考摘要 | 词面或语义参考相似度 | 证据共同可见或逐事实正确性 |

最终目标事项正确性需另行核对，重点包括状态、负责人、数量、范围、条件及不确定性。
例如“负责人变更识别正确，但扩大到其他设计任务”不能视为完整正确。
该正确性评估不自动由本覆盖指标推导。

## 5. 项目验收目标

预先约定的挑战集证据组织目标：**共同窗口覆盖率至少达到 80%**。

80% 是本项目的工作目标，不是领域公认标准，也不是事实正确率的门槛。
达到该目标不代表系统能够无需人工确认生成最终纪要。

正式验收应使用未参与开发或调参的案例，报告 `命中事项数 / 可评估事项数`、比例、
置信区间以及评估完整性。若一场会议包含多个事项，统计不确定性时需考虑同一会议内的相关性，
不要将双向检索当作两个独立样本。

开发案例达到目标后，可停止围绕这些案例继续追求全部命中，转而验证最终摘要和未见案例。

## 6. 当前开发案例结果

三条人工插入事项分别涉及供电方案变更、任务负责人变更、授权条件未满足。
原始会议内容来自 AMI；插入事项是可控测试内容，不是原始 AMI 会议事实。

| 方法 | 供电方案变更 | return kit 负责人变更 | hallway trial 授权条件 | 事项命中数 | 共同窗口覆盖率 |
|---|---|---|---|---:|---:|
| baseline 原时间窗口 | 未共同覆盖 | 未共同覆盖 | 未共同覆盖 | 0/3 | 0% |
| V2 信息加权绝对分数 | 未共同覆盖 | 未共同覆盖 | 未共同覆盖 | 0/3 | 0% |
| V3 相对优势与多样性 | 窗口 0、4 | 窗口 8 | 窗口 0、9 | 3/3 | 100% |

窗口编号从 0 开始。三种方法共用同一全局 selected KV；每窗口最多补充两个远距离块，
V2、V3 的候选选择策略不同。baseline 无额外补充，因此这不是等量局部证据实验。

V3 的补充方向另行记录如下，不作为主指标的分母：

| 事项 | 开头检索结尾 | 结尾检索开头 |
|---|---|---|
| 供电方案变更 | 命中 | 命中 |
| return kit 负责人变更 | 未命中 | 命中 |
| hallway trial 授权条件 | 命中 | 命中 |

方向命中共 5/6（83.3%）；按事项共同窗口覆盖则为 3/3（100%）。两种口径不能混用。

这些案例已经用于诊断和修改 V3，属于开发结果；样本量仅为 3，不能据此证明未见案例能达到
80%，也不能证明最终摘要精准度提高。V3 新一轮生成质量需与检索结果分开记录。

## 7. 结果来源与复现

原始成对运行：

```text
test_result/experiment_3_endpoint_3/20261125_052753_701837
```

V2 检索与诊断：

```text
test_result/experiment_3_retrieval_v2/20261125_060053_572406
test_result/experiment_3_retrieval_diagnostic/20261125_061140_471543
```

V3 检索与诊断：

```text
test_result/experiment_3_retrieval_v3/20261125_062107_833938
```

原始运行中 `selection.json` 保存精确选中位置及 hash，`source.json` 保存原文与 ID；
V3 的 `retrieval.json` 保存各窗口实际合并的位置，`target_diagnostics.json` 保存目标块、
候选排名与补充情况。当前结果通过这些记录核对，没有将候选命中直接当作摘要正确。

答案标注为 `input/ami_endpoint_challenge_3/answer_key.json`。
它仅在普通检索完成后用于诊断，不参与检索加权或生成提示词。
运行方法见 [README.md](README.md)。

## 8. 论文中可使用的描述

> 我们定义关键证据共同窗口覆盖率，衡量一个目标事项的全部必要证据是否共同进入至少一个
> 局部 specialist 的输入。该指标用于诊断证据组织能力，与最终摘要正确性分开评估。
> 在三个用于方法开发的可控案例中，V3 将共同窗口覆盖率从 0/3 提高至 3/3。
> 由于案例已参与开发且数量有限，该结果不构成对未见数据泛化能力的证明。

> We define Key Evidence Co-location Coverage as the proportion of annotated items for
> which all required source evidence is jointly available in at least one local
> specialist window. It measures evidence organization rather than summary factuality.
> On three controlled development cases, V3 increased coverage from 0/3 to 3/3.
> Since these cases informed method development and the sample is small, this result
> does not establish generalization to unseen cases.
